# MoodFlow AI 音乐助手项目总结

## 技术栈

- 前端：React 19、TypeScript、Vite、Zustand、React Router、Tailwind CSS，结合 Framer Motion 和 Three.js 实现音乐播放器、AI 对话与探索界面，通过 SSE 接收流式回答和任务进度。
- 业务后端：Java 21、Spring Boot 4、Spring MVC，使用 HttpSession 管理登录态，封装网易云音乐 API，提供歌曲搜索、播放资源、歌词、收藏和歌单管理接口。
- AI 服务：Python、FastAPI、LangChain、LangGraph、Pydantic，接入兼容 OpenAI 协议的大模型，结合规则路由、意图分类模型和 JEV 决策服务实现任务识别、工具调用与 Agent 协作。
- 数据与检索：PostgreSQL 保存检查点、任务账本和用户记忆，pgvector 支持长期记忆语义检索；Qdrant、Qwen3 Embedding、BM25 和 Qwen3 Reranker 支撑音乐知识 RAG，DeepEval 与自建评测工具验证检索及回答质量。
- 工程与扩展：使用 Docker Compose、Nginx 组织部署；Redis 的原子预算、限流、会话缓存、派生缓存和事件能力已在独立特性分支实现，按开关启用，当前工作分支未合并。

## 具体业务描述

- 项目面向音乐用户，将在线听歌、自然语言操作和音乐知识探索整合到同一应用中。用户既可以搜索、播放和管理音乐，也可以围绕当前歌曲发起分析、推荐及连续追问，减少在播放器、歌单和外部资料之间切换。
- 音乐播放与管理：支持扫码登录、歌曲及音乐实体搜索、歌词查看、播放队列、进度与音量控制，并提供云端红心收藏、自建歌单创建、增删歌曲和确认后删除歌单等能力。
- AI 音乐助手：根据当前歌曲和对话上下文回答问题，将“播放这首歌”“加入歌单”“暂停后继续介绍”等自然语言请求转为有序任务，区分服务端业务操作与浏览器播放器动作，并接收前端执行回执。
- 世界线探索：以歌曲、歌手或专辑为入口，结合音乐目录事实与 RAG 证据展示关系图谱和解释文本，支持沿流派、时代、场景及影响关系继续探索，并保存分支、版本和来源信息。

## 技术亮点

- 断点续跑：基于 LangGraph Checkpointer、PostgreSQL 任务账本和操作回执保存执行进度。恢复时核对检查点、外部操作结果和预算消耗，复用已确认结果，对未知写入先对账，降低重跑造成重复操作的风险。
- 工具治理：共享音乐服务与播放器工具实现，按 Agent 职责及当前任务裁剪工具范围。执行前校验参数、可信实体来源和本轮用户授权，结合调用上限、超时、去重及前端 ACK，约束越权调用和重复执行。
- 全链路与 RAG 评测：建立组件回放、会话回放、跨进程恢复和真实服务验证，覆盖正常、边界与失败路径；RAG 分别评估检索、重排、上下文和回答，独立统计人工 Gold 与合成样例，避免混用结果。
- Context Engineering：采用 Collect → Select → Dedup → Budget → Compress → Assemble 流水线，按任务选择歌曲上下文、业务状态、历史、画像和知识证据；通过 lite/full 两阶段入口及来源配额控制输入规模，记录上下文取舍。
- Java 后端：集中封装网易云音乐接口和服务端登录态，统一 DTO、响应格式与异常处理。AI 工具复用可信业务接口获取音乐实体、执行收藏及歌单操作，保持账号身份与业务校验的一致性。
- Memory：短期记忆复用 State 与 Checkpointer，长期记忆按可信 user_id 隔离，分别保存用户偏好与情景记忆，通过 PostgreSQL、pgvector 和版本化画像召回；结果经上下文预算筛选后参与后续回答。
- Multi-agent 功能设计：GeneralChat 负责交流，Curator 负责当前歌曲分析和音乐操作，Explorer 负责世界线探索；按能力归属分配任务，为包含聊天、播放和探索的组合请求保留执行顺序与依赖。
- Multi-agent 总架构：默认 Foundation 以主图组织四类能力子图，另提供三 Agent Handoff 协作模式。统一任务结果和转交契约，仅开放 GeneralChat ↔ Curator ↔ Explorer 四条转交边，并限制无进展回转。
- Prompt 版本化管理：通过不可变 PromptBinding 注册提示词 ID、版本、变体及 SHA-256 摘要，校验 Agent 与调用阶段的归属；调用清单记录所用版本，便于追溯输入和比较提示词调整效果。
- RAG：构建来源采集、解析清洗、分块、知识加工、索引、查询理解、混合召回、重排和证据组装链路。融合语义检索与 BM25，再以重排结果支撑世界线叙述，通过来源引用和实体约束减少无依据的关联。
- Redis 扩展：独立分支使用 Lua 原子预算预留和滑动窗口限流，结合 TTL 缓存会话、画像及上下文派生数据，并提供去重占坑、播放计数与进度 Stream；关键业务事实仍由 PostgreSQL 仲裁，缓存故障按既定策略回源。
- Token 预算管理：对单次模型调用、单个 Agent 和整次任务分别设置预算，调用前预留输出空间，调用后按真实用量结算并持久化。临近上限时依次裁剪历史、提取摘要和停止可选来源，恢复任务继续沿用原账本。
